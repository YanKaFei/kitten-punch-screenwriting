# Regression Cases

用于每次升级后验证 Skill 是否仍遵守核心不变量。

## Case 01：人物越权知道
前一场只有 A 看见密钥，下一场 B 未与 A 接触却直接使用密钥。
期望：G08 FAIL；不得用“B可能推测到”自我合理化。

## Case 02：物件瞬移
枪在 Scene 3 被警察扣押，Scene 5 主角无取回过程直接掏枪。
期望：G09 FAIL。

## Case 03：重复追杀
主角三场连续逃跑，对手只是人数增加，主角策略不变。
期望：G04/G07 FAIL，要求改变策略或状态，不是继续加人。

## Case 04：漂亮废戏
两人长谈很感人，但开场/结尾关系、信息、资源、选择均不变，且不制造下一场压力。
期望：G05/G06 FAIL。

## Case 05：高潮外挂
高潮首次出现主角会黑客入侵，此前没有建立。
期望：G10 FAIL。

## Case 06：伪两难
“救全城还是拿一杯咖啡”。
期望：危机设计失败，要求双方都有真实代价。

## Case 07：Promise 超期
第一幕反复强调一把只能开一次的钥匙，结局完全没用也没解释。
期望：G11 FAIL。

## Case 08：对话泄露作者分析
人物说“我现在愤怒是因为童年创伤让我无法相信别人”。
期望：G12/G14 FAIL；改为行为和策略。

## Case 09：短剧直给但因果成立
女主第一场直接公布婚讯，引爆身份冲突，信息来源与人物关系成立。
期望：不因“直给”自动判错；按 Vertical Route 评估。

## Case 10：用户只改对白
原剧情存在但用户明确只要求口语化对白。
期望：不得擅自重构剧情，只指出结构问题可另列风险。

## Case 11：关系跳变
上一场 A 刚背叛 B，下一场无补偿/新证据直接恢复完全信任。
期望：Relationship State 冲突，FAIL。

## Case 12：合理开放结局
高显著度谜团未完全解释，但人物完成不可逆选择，未解部分本身构成主题余味且已有证据边界。
期望：允许 DELIBERATELY_UNPAID，而不是机械要求全解。
