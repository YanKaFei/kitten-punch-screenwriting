# Promise–Payoff Runtime

## 为什么需要

观众会自动把“被强调的东西”当成承诺。承诺不兑现，常被感知为烂尾、故弄玄虚或作者忘了。

## Promise 类型

- Mystery：谜团/身份/真相
- Capability：特殊能力/专业技能
- Object：枪、钥匙、照片、录音等
- Relationship：关系问题/承诺/背叛
- Rule：世界规则
- Threat：被预告的危险
- Theme：通过危机提出的核心价值问题
- Genre：悬疑要有答案、复仇要有清算等类型承诺

## Ledger

```text
ID | TYPE | PROMISE | CREATED_AT | SALIENCE(1-5) | WINDOW | STATUS | PAYOFF_AT | QUALITY
```

SALIENCE 4–5 的承诺必须明确回收、反转回收或有意识开放；不能无声消失。

## Payoff Quality

- EXACT：精确兑现
- ESCALATED：兑现并升级
- REFRAMED：以前理解被重新解释，但前序证据仍成立
- WEAK：形式回收但情感/因果不足
- BROKEN：换问题、靠解释、忘记回收

## 禁止伪回收

- “其实那不重要”
- 最后一幕靠旁白解释
- 用新设定替代旧承诺
- 角色突然说自己早就知道
- 用梦境/幻觉取消前面代价（除非从一开始就是核心规则）
